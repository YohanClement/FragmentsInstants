# Phase 1 Data Model: Les Fragments d'Instants — V1

**Date**: 2026-09-28
**Feature**: [spec.md](./spec.md) | **Research**: [research.md](./research.md)

All entities are persisted via Spring Data JPA against the local SQLite file. Per the
Données brutes d'abord constitution principle, only raw entities below are stored — no
aggregate/statistic is ever persisted as a column or row; every statistic in `contracts/` is
computed on read from these tables.

**Timezone**: every "calendar day" concept used below (a session's day, "today", week
boundaries, midnight resets) is anchored to the fixed workstation timezone, `Europe/Paris`
(see [plan.md](./plan.md), Technical Context) — not UTC and not the browser's timezone, since
front and back always run on the same local machine in V1.

## Identifier strategy: Long (auto-increment) — pending Task 1 spike confirmation

**Decision**: entities below use `Long` primary keys generated by SQLite's native
`INTEGER PRIMARY KEY AUTOINCREMENT` (via `@GeneratedValue(strategy = GenerationType.IDENTITY)`),
not UUIDs.

- **Rationale**: single local user, no multi-device sync, no distributed ID generation need in
  V1 (constitution Local-first/Simplicité) — an auto-increment integer is SQLite's most native,
  best-supported primary key form, and avoids depending on the already best-effort-maintained
  `hibernate-community-dialects` SQLite dialect to also correctly support UUID generation
  strategies.
- **Verification required before this is final**: this choice, along with the SQLite + Flyway +
  Hibernate wiring itself, **must be the first task in `tasks.md`** — a small feasibility spike
  that stands up one migrated table, inserts/reads a row through Spring Data JPA with an
  auto-increment `Long` id, and documents the result. **Fallback, if the spike finds a blocking
  issue** with `IDENTITY` generation under the community SQLite dialect: switch every `id` below
  to `UUID` (`@GeneratedValue` with a UUID strategy, application-assigned if needed) — a
  documented, ready alternative, not a redesign. **Fallback, if the spike finds SQLite/Flyway/
  Hibernate wiring itself unreliable**: fall back to an embedded H2 database in
  PostgreSQL-compatibility mode as the local file store instead of SQLite, keeping the same
  entity/repository code (JPA abstracts the SQL dialect) — documented here so the spike's outcome
  directly decides which path `tasks.md` continues on, before any other backend task is built on
  top of an unverified stack.

The tables below are written against the primary decision (`Long`); every `id` column should be
read as "Long, or UUID if the Task 1 spike triggers the documented fallback".

## Task

Represents a to-do item.

| Field | Type | Rules |
|---|---|---|
| `id` | Long (PK) | Auto-increment (see Identifier strategy above). |
| `title` | String | Required, non-blank. |
| `description` | String | Optional. |
| `estimatedMinutes` | Integer | Optional; if absent, contributes weight 0 (FR-027, edge case). If present, >= 0. |
| `priority` | Enum: `BASSE, NORMALE, HAUTE, CRITIQUE` | Required, default `NORMALE`. |
| `dueDate` | LocalDate | Optional. |
| `status` | Enum: `ACTIVE, EN_PAUSE, TERMINEE` | Required, default `ACTIVE`. |
| `completedAt` | Instant | Set when status becomes `TERMINEE`; cleared (`null`) when reopened (FR-032). |
| `createdAt` / `updatedAt` | Instant | Managed automatically. |
| `tags` | Many-to-many → Tag | Always at least one row (FR-035); defaults to `Autre` at creation if none chosen. |

**Derived (never stored)**: real time spent, remaining time — computed from associated
`PomodoroSession` rows (FR-029).

**State transitions**:

```
ACTIVE  <--pause/resume--> EN_PAUSE
ACTIVE  --complete-->  TERMINEE (completedAt = now)
EN_PAUSE --complete--> TERMINEE (completedAt = now)
TERMINEE --reopen--> ACTIVE (completedAt = null, time spent unchanged — FR-032)
```

## PomodoroSession

Represents one Pomodoro timer run, submitted by the front end only once it has ended
(completed or interrupted) — never while running (per the front-end timestamp-based timer
design).

| Field | Type | Rules |
|---|---|---|
| `id` | Long (PK) | Auto-increment (see Identifier strategy above). |
| `mode` | Enum: `FOCUS, PAUSE_COURTE, PAUSE_LONGUE` | Required. |
| `taskId` | Long (FK → Task, nullable) | Optional; pauses are typically unassociated, Focus sessions usually associated. Nullable so a deleted task doesn't require cascading deletion of past sessions (see spec edge case: session time stays counted after task deletion → FK is `ON DELETE SET NULL`). A session with `taskId = null` — whether never assigned or orphaned by a task deletion — is attributed to the `Autre` tag in tag-breakdown statistics (FR-031, FR-039 wording aside — see contracts). |
| `startedAt` | Instant | Required, client-supplied (the front end's own timer timestamp). The session's calendar day = the day of `startedAt` in `Europe/Paris` (spec decision: "une session est rattachée au jour de son début"). |
| `endedAt` | Instant | Required, client-supplied, `>= startedAt`. |
| `actualDurationSeconds` | Integer | **Server-computed only** — `= endedAt - startedAt` in seconds, derived by the backend on write from the two timestamps above. The API request body does not accept a client-supplied duration value (FR-012): this guarantees a single source of truth and prevents a front-end bug or clock skew from reporting an inconsistent duration. |
| `completionStatus` | Enum: `TERMINEE, INTERROMPUE` | Required. Only `FOCUS` + `TERMINEE` sessions count toward "nombre de Pomodoros" / long-break counter (FR-033). All `FOCUS` sessions (`TERMINEE` or `INTERROMPUE`) with `actualDurationSeconds >= 60` count toward total focus time; sessions under one minute are ignored entirely from focus-time sums. |
| `createdAt` | Instant | Server-assigned receipt timestamp (audit only, not used in calculations). |

No update/delete endpoint is exposed for sessions in V1 — they are immutable once recorded,
consistent with Données brutes d'abord.

## Tag

| Field | Type | Rules |
|---|---|---|
| `id` | Long (PK) | Auto-increment (see Identifier strategy above). |
| `name` | String | Required, unique (case-insensitive). |
| `isDefault` | Boolean | `true` for the eight seeded tags (Écriture, Administratif, Maison, Enseignement, Créatif, DIY, Recherche, Autre), `false` for user-created tags. |
| `isProtected` | Boolean | `true` only for `Autre`. Enforced at the application layer: rename/delete requests on a protected tag are rejected (FR-036). |

**Seed data** (Flyway migration): the 8 default tags, with `Autre` flagged `isDefault=true,
isProtected=true`.

**Cascade rule on delete** (application-layer, not a DB cascade): deleting a non-protected tag
that is a task's *only* tag reassigns that task to `Autre` before the tag row is removed
(FR-036). Deleting a tag that is one of several tags on a task simply removes the association.

## TaskTag (join table)

Implicit many-to-many join table (`task_id`, `tag_id`), no additional attributes.

**Tag-breakdown allocation is computed session by session, not from a task's cumulative real
time** (FR-031). For a given period (today or this week), take every eligible `PomodoroSession`
(mode `FOCUS`, `startedAt` day within the period, `actualDurationSeconds >= 60` — the same
eligibility as `FocusTimeTotal`) and, for each one individually:

- if it has a `taskId`, split its `actualDurationSeconds` evenly across that task's *current*
  tags (read at aggregation time, not at the session's own start time — a task's tags can change
  after old sessions were recorded);
- if it has no `taskId` (never assigned, or its task was since deleted), attribute its full
  `actualDurationSeconds` to `Autre`.

Sum these per-tag allocations across all eligible sessions in the period, then apply
`TagPercentageBreakdown`. This is a read-time calculation only — never stored.

## Domain formulas (pure, no Spring dependency, TDD with JUnit 5 + AssertJ)

Each is a standalone pure Java class/function in `domain/`, taking primitives/records in and
returning primitives/records out — no entity, no repository, no Spring annotation. Exactly
**8 formulas** in V1 (the "variation vs. previous value" formula considered during planning was
dropped as unused — see research.md; the mood/fatigue weekly average was kept and is now surfaced
on the dashboard, see below).

| # | Formula | Inputs | Output | Edge case handling |
|---|---|---|---|---|
| 1 | `TaskWeight` | estimated minutes (nullable), priority coefficient | weight | `null`/absent estimate → weight 0 (FR-027, spec edge case). |
| 2 | `DailyProgress` | sum of weights of tasks completed today, sum of weights of tasks planned today (FR-006 definition) | percentage | denominator 0 → 0% (never an error) (FR-028). |
| 3 | `RemainingTime` | estimated minutes, real minutes | `max(0, estimated - real)` | — (FR-029). |
| 4 | `TagPercentageBreakdown` | list of (tag → allocated time) pairs already aggregated session by session (see TaskTag above), total time for the period | percentage per tag | total 0 → every tag at 0% (FR-031). |
| 5 | `WeeklyMoodFatigueAverage` | list of `MoodEntry` present in the current week (only days with data) | average per scale, or "no data" | empty list → explicit "no data" marker, never 0 (FR-030, constitution V). Surfaced on the dashboard as three weekly cards (FR-039). |
| 6 | `PomodoroDailyCount` | list of today's `PomodoroSession` | count of `FOCUS` + `TERMINEE` sessions today | interrupted/other-mode sessions excluded (FR-033). |
| 7 | `PomodorosBeforeLongBreak` | today's completed Focus count (`count`), configured threshold (`threshold`) | `(remaining: int, nextBreakType: COURTE\|LONGUE)` | `m = count % threshold`; if `count > 0 && m == 0` → `remaining = 0`, `nextBreakType = LONGUE` (a long break is due now); else → `remaining = threshold - m`, `nextBreakType = COURTE`. Recomputed from today's sessions only — resets naturally at midnight since "today" changes (FR-037); never stored. Exposed via the dashboard (FR-038). Boundary cases (`count = 0`, `count` an exact multiple of `threshold`, `threshold = 1`) are explicit JUnit cases, not left implicit. |
| 8 | `FocusTimeTotal` | list of today's `FOCUS` sessions (any completion status) | total seconds | sessions with `actualDurationSeconds < 60` excluded from the sum (spec decision). |

## Business-rule error handling (FR-040)

Every business-rule rejection across the whole API (renaming/deleting the protected `Autre` tag,
a mood/fatigue score outside 1–7, an invalid task/session transition, etc.) uses **one single
error code**, not a different code per rule: HTTP `422 Unprocessable Entity` with body
`{ "code": "REGLE_METIER_VIOLEE", "message": string }`, where `message` is the specific,
bienveillant explanation for that particular rejection. This is distinct from plain request
validation (missing required field, malformed JSON), which stays a standard `400` from Spring's
own validation — `REGLE_METIER_VIOLEE` is reserved for domain-rule violations raised by the
`application/` layer. See [contracts/api-overview.md](./contracts/api-overview.md).

```
Task 1---* PomodoroSession (nullable FK, ON DELETE SET NULL)
Task *---* Tag (join table task_tag)

```

All primary/foreign keys above are `Long`, pending the Task 1 feasibility spike (see Identifier
